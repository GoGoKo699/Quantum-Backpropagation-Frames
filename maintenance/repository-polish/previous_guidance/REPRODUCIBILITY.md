# Reproducibility

Use Python 3.13 and the pinned NumPy requirement. Each run records its actual
interpreter and dependency versions; historical run versions are not rewritten.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python tools/verify_inputs.py
python -m unittest discover -s tests -v
```

The complete integration gate requires a clean, full Git checkout containing the
pinned PF-02 commit. Clone normally, or unshallow an existing checkout first:

```bash
python tools/integration_check.py --output runs/integration-01
```

The output directory must be new and strictly below runs/. The gate records
source hashes, Git commit, environment, commands and failures in RUN.json. It:

1. compares frozen Git objects and working files with the PF-02 baseline;
2. runs all repository tests and the existing PF-01 diagnostics;
3. runs both supplied validators in temporary copies;
4. reruns the same PF-02 acceptance grid into a new output directory;
5. compares every scenario and candidate cost row with the saved PF-02 record;
6. verifies the two numerical boundary corrections and clean final checkout.

Numeric regression tolerance is 1e-12 relative and absolute; category fields,
counts and winner selections must match exactly. Machine environment strings
are recorded but excluded from the numerical comparison. No parameter ranges,
prices or scientific acceptance criteria are changed. The full older MR-01
comparison tables are not regenerated by this gate.

## Individual scientific diagnostic reruns

```bash
python tools/reproduce.py parity --output runs/parity-01
python tools/reproduce.py matched --output runs/matched-01
```

These copy the supplied packets into temporary directories. Imported sources and
stored validation.json files are not overwritten. The optional matched-full
mode regenerates the older full comparison packet and is not required for this
integration review; do not enlarge its targets without a bounded work order.

## CI and evidence

The single active validation workflow runs on main/review pushes, pull requests
targeting main, and manual dispatch. It uses contents: read, does not persist
checkout credentials, and never commits or pushes. Logs are uploaded even on
failure as a run-specific artifact with a requested 30-day retention. Keep a
local copy of an artifact when long-term evidence retention is needed. Verified
run receipts can be added by a later explicit repository change.

The old write-enabled workflows are retained as text in
results/PF-03/retired_workflows/, not under .github/workflows/.
PACKAGE_MANIFEST.json is the frozen initialization inventory, not a current
working-tree manifest. The integration gate uses the pinned Git tree and per-run
source SHA-256 values instead of rewriting that historical snapshot.

A green run establishes the checks actually executed. It is not an independent
proof, exhaustive novelty audit, hardware result, or quantum-advantage claim.
